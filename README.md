# 作业文件批量整理工具

一个用 Python + PySide6 写的图形化小工具，用来整理学生作业文件。

分五个功能模块，对应三个原始需求 + 两个新增需求：

| 模块          | 能力                                                              | 会修改文件吗 |
| ----------- | --------------------------------------------------------------- | ------ |
| 需求 1 · 扫描列出 | 列出文件的大小、修改时间，支持按扩展名过滤                                           | 否，纯只读  |
| 需求 2 · 批量改名 | 自选**原/新文件名格式**，可用**学生信息表**补全学号姓名、用**作业白名单**指定作业名，**先预览、确认后才改**，缺学号姓名的**标红不改** | 会（需确认） |
| 需求 3 · 归档报告 | 按类别/学期移入子文件夹，生成整理报告，**支持撤销**                                    | 会（需确认） |
| 新增 · 作业检查   | 导入**任意检索信息**与所有文件名逐段比对，产出**输入信息 / 识别份数 / 达标份数 / 未达标份数**汇总表，达标 ≥ 1 份**标绿**否则**标红**，全绿给**总绿勾** | 否，纯只读  |
| 新增 · 作业归类   | 文件名**切成任意多段**逐段比对**关键词表**，命中哪段就用该段建文件夹，多命中**复制副本**，**先预览、可撤销**   | 会（需确认） |

## 一、快速开始

### 1. 环境要求

- Python 3.10 或更高版本
- PySide6（图形界面）
- 可选依赖：python-docx（读 Word）、pypdf（读 PDF）、openpyxl（读 Excel）

### 2. 安装依赖

```bash
pip install PySide6 python-docx pypdf openpyxl
```

### 3. 启动图形界面

```bash
python run.py
```

### 4. 生成演示数据（可选）

如果你想先看看效果，可以生成一批模拟的学生作业文件：

```bash
python make_demo_data.py ./demo_data
```

这会生成 17 个文件，其中包括：

- 8 份字数不同的 `.docx`
- 3 份 `.txt`（其中一份只有 5 个字）
- 2 份 `.pdf`
- 2 个不符合命名规则的文件（用来验证「跳过」逻辑）
- 1 个重名冲突场景（用来验证「防覆盖」逻辑）

## 二、界面使用说明

界面顶部是**公共区**，所有功能共用：

```
① 选择目录与扫描条件
   作业目录：[E:/计协应聘                ] [浏览...]
   扩展名过滤：[.docx .pdf                ] □ 包含子文件夹
                                                     [ 扫描 ]
```

**操作顺序**：先填目录 → 点「扫描」→ 再切到下面的标签页做具体操作。

> **「字数要求」只在作业检查页出现**：早先它被放在顶部公共区，导致切到改名、
> 归档等无关标签页时也会看到它，容易让人误以为其它功能也受字数约束。
> 现已移入「新增 · 作业检查」标签页内部，**只有进入该页才显示**。
> 详见下文「新增 · 作业检查」章节。

五个标签页分别是「需求1 · 扫描列出」「需求2 · 批量改名」「需求3 · 归档报告」
「新增 · 作业检查」「新增 · 作业归类」。

界面底部有一块**输出区**，所有操作的结果、报告、错误信息都会打印在那里，可以选中复制。

**大块内容的「放大」与「折叠」**：界面里有几处会显示大段内容，它们占用的空间不小，
但平时又不必一直全部展开。为此提供了两个手段。

**手段一：折叠。** 需求2 与「作业归类」顶部的说明较长，默认**只显示一行概要**：

```
▶ 识别规则说明（点击展开全部细则）
```

点一下标题行即展开全部细则（箭头变为 `▼`），再点一次收起。这样规则随时可查，
但平时只占一行，把空间让给表格。

作业归类页的说明标题为「**归类规则说明（逐段匹配，不限段数，点击展开）**」，
展开后完整交代：切段与逐段比对、段数不限、表里内容任意、命中段作文件夹名、
多命中复制副本、未命中原地不动、表空不可用。

**手段二：放大。** 下面这些区域各配一个 **「放大 ⤢」** 按钮，点一下弹出近乎整屏的
窗口把内容完整展开，看完点「关闭」即可：

| 位置 | 放大后 | 能否编辑 |
|---|---|---|
| 学生信息表（需求2） | 近全屏 | ✅ 可编辑，关闭时改动**自动回写** |
| 作业白名单（需求2） | 近全屏 | ✅ 可编辑，关闭时改动**自动回写** |
| 改名预览表格（需求2） | 近全屏 | ❌ 只读，行数多时用来通览 |
| 学期区间设置（需求3） | 近全屏 | ✅ 可编辑 |
| 操作输出 / 报告（底部） | 近全屏 | ❌ 只读 |
| 整理报告（需求3） | 近全屏 | ❌ 只读 |
| 关键词表（作业归类） | 近全屏 | ✅ 可编辑，关闭时改动**自动回写** |
| 归类预览表格（作业归类） | 近全屏 | ❌ 只读，行数多时用来通览 |
| 检索信息（作业检查） | 近全屏 | ✅ 可编辑，关闭时改动**自动回写** |
| 检查汇总表 / 字数明细表（作业检查） | 近全屏 | ❌ 只读，行数多时用来通览 |

表格放大窗口会**完整复制**原表格的行列、表头、内容与配色——标红的行在放大后依然是标红的。

**手段三：整页滚动。** 需求 2 是内容最多的一页（规则说明 + 学生信息表 +
作业白名单 + 格式设置 + 按钮 + 预览表）。为避免窗口不够高时底部内容被挤掉，
这一页整体套在**滚动区**里：鼠标滚轮在页面**任意位置**都能上下滚动，
把每个区块都看全，不用先去点某个特定的框。

## 三、五个功能的详细说明

### 需求 1 · 扫描列出

点「扫描」后，表格列出目录下所有文件：

| 序号 | 文件名                    | 大小      | 修改时间                | 字数  |
| -- | ---------------------- | ------- | ------------------- | --- |
| 1  | 20230101_张三_第一次作业.docx | 35.0 KB | 2026-10-06 10:13:34 | 877 |

**扩展名过滤**的写法很宽松，下面几种都行：

```
.docx .pdf          空格分隔
.docx,.pdf          逗号分隔
docx pdf            不带点也可以
PDF                 大写也可以
```

留空 = 不过滤，显示全部文件。

---

### 需求 2 · 批量改名

**改名规则**：程序按你选定的「原文件名格式」识别每个文件，再按「新文件名格式」重命名。

默认使用「**自动识别**」——不需要预先知道文件名是什么结构，程序自己看。
识别分两步走：**先查作业白名单，再按段数规则判断**。

#### ⓪ 作业白名单（最优先，可选）

在自动识别模式下，程序**第一步**就先拿文件名各段去比对「作业白名单」：
**与表中某条完全一致的那一段，直接认定为作业名**，不再进入下面的段数规则。

这条规则排在最前，因为它最可靠——白名单是你亲手写下的答案，
比程序靠特征词猜要准得多。它专门解决这类问题：

> `宏观经济学_王小明_20230202.txt`
> 两段文本都不含「作业/报告/实验」等特征词、长度也相近，
> 程序只能按「取后置段」把 `王小明` 当成作业名。
> 把 `宏观经济学` 写进白名单后，识别结果被纠正为正确的作业名。

```
# 每行一个作业名，# 开头的是注释行
第一次作业
宏观经济学
读书笔记
```

| 白名单 | 行为 |
|---|---|
| **留空** | 跳过本步，完全按下面的段数规则判断（即原有行为不变） |
| **有内容** | 先做精确匹配；表中没有匹配项时，仍按段数规则继续判断 |
| 只在「自动识别」下生效 | 固定排列时作业名由你指定的字段位置决定，白名单不参与（界面会提示） |

**重要限制**：白名单只决定「哪一段是作业名」，**不能用来代替学号或姓名**。
文件名里两者都没有时，即使该段命中了白名单、确实被认成了作业名，文件**照样标红不改**。

界面提供四个按钮：**导入 TXT** / **填入示例** / **导出示例** / **清空**，
并配一个**放大按钮**，作业名多时可以近全屏编辑。

#### ① 自动识别规则（默认）

程序先把文件名按 `_`、`+`、空格切成若干**段**，再看每段的内容类型，最后套用这张规则表：

| 段数 / 内容           | 判定                      | 结果          |
| ----------------- | ----------------------- | ----------- |
| **仅 1 段**         | 缺少学号或姓名                 | **标红，不予通过** |
| **2 段：数字 + 文本**   | 数字段作学号，文本段**直接**作作业名    | 通过          |
| **2 段：文本 + 文本**   | 含「作业/报告/实验/第N次」等字样者作作业名 | 通过          |
| **3 段：数字 + 两段文本** | 数字段作学号，另两段按上面的「文本 + 文本」规则定作业名 | 通过 |
| **其余情况**（如两段都是数字、四段以上） | 无法判断哪个是学号 | **标红，不予识别** |

两段文本时，另一段**一律作姓名**（不校验是否真的像姓名）。具体分三种子情况：

| 情形         | 作业名     | 姓名 |
| ---------- | ------- | -- |
| 前段含字样，后段不含 | 前段      | 后段 |
| 后段含字样，前段不含 | 后段      | 前段 |
| **两段都含字样** | **后置段** | 前段 |
| 两段都不含字样    | **后置段** | 前段 |

三段（数字 + 两段文本）中两段文本的判断**与上面完全一致**，只是额外多出一个学号，
且数字段出现在哪个位置都可以：

| 原文件名                     | 识别结果                   | 命中规则          |
| ------------------------ | ---------------------- | ------------- |
| `20230001_张三.docx`       | 学号 `20230001`，作业名 `张三` | 数字+文本         |
| `张三+第一次作业.docx`          | 姓名 `张三`，作业名 `第一次作业`    | 含作业字样         |
| `第一次作业_王五.docx`          | 姓名 `王五`，作业名 `第一次作业`    | 含作业字样         |
| `作业_报告.docx`             | 姓名 `作业`，作业名 `报告`       | 两段都含 → 后置     |
| `张三_李四.docx`             | 姓名 `张三`，作业名 `李四`       | 都不含 → 后置      |
| `20230001_张三_第一次作业.docx` | 学号 `20230001`，姓名 `张三`，作业名 `第一次作业` | 数字+两段文本 |
| `数据结构实验_王五_20230103.docx` | 学号 `20230103`，姓名 `王五`，作业名 `数据结构实验` | 数字+两段文本 |
| `第一次作业_20230001_张三.docx` | 学号 `20230001`，姓名 `张三`，作业名 `第一次作业` | 数字+两段文本（数字居中） |
| `孤零零.docx`               | —                      | **单段，标红**     |
| `20230001_20230002.docx` | —                      | **两段都是数字，标红** |
| `20230001_张三_李四_王五.docx` | —                      | **四段，标红**     |

**分隔符**：只支持 `_`、`+`、空格三种（半角与全角空格都认）。连续分隔符按一个处理，例如 `20230001__张三` 等同于 `20230001_张三`。

#### ② 也可以指定固定格式

如果文件名结构是已知的固定排列，可以在「原文件名格式」下拉框里直接指定：

| 下拉选项         | 对应结构                       |
| ------------ | -------------------------- |
| **自动识别（推荐）** | 按上表规则推断                    |
| 学号_姓名_作业名    | `20230101_张三_第一次作业.pdf`    |
| 姓名_学号_作业名    | `张三_20230101_第一次作业.pdf`    |
| 学号_作业名       | `20230101_第一次作业.pdf`       |
| 姓名_作业名       | `张三_第一次作业.pdf`             |
| 作业名_学号       | `第一次作业_20230101.pdf`       |
| 作业名_姓名       | `第一次作业_张三.pdf`             |
| 学号_姓名_作业名_序号 | `20230101_张三_第一次作业_01.pdf` |

指定固定格式时，程序会额外校验"声明为学号/姓名的那段内容是否对得上"——对不上同样标红。
  
选好之后，程序就按这个结构去切分文件名。

#### ③ 新文件名格式可自选

「**新文件名格式**」下拉框提供常用排列，选中后会自动把模板填进下面的输入框：

| 下拉选项      | 模板                    |
| --------- | --------------------- |
| 作业名_学号    | `{title}_{id}`        |
| 作业名_姓名    | `{title}_{name}`      |
| 作业名_学号_姓名 | `{title}_{id}_{name}` |
| 作业名_姓名_学号 | `{title}_{name}_{id}` |
| 学号_作业名    | `{id}_{title}`        |
| 姓名_作业名    | `{name}_{title}`      |
| 作业名       | `{title}`             |

也可以在输入框里直接手写模板，三个占位符的含义：

| 占位符       | 含义  | 例子         |
| --------- | --- | ---------- |
| `{id}`    | 学号  | `20230101` |
| `{name}`  | 姓名  | `张三`       |
| `{title}` | 作业名 | `第一次作业`    |

#### ④ 学生信息表（学号 ↔ 姓名对照）

如果文件名里只有学号没写姓名，或者只有姓名没写学号，可以交给**信息表**来补全。

信息表的两种输入方式：

- **直接粘贴**：在界面文本框里逐行输入；
- **导入 TXT 文件**：点「导入 TXT 文件」选一个现成的名单。

**格式很宽松**，下面这几种写法都能认：

```text
# 井号开头的是注释，程序自动忽略
学号,姓名            ← 表头会被自动跳过
20230001,张三        ← 英文逗号
20230002 李四        ← 空格
20230003，王五        ← 中文逗号
20230004:赵六        ← 冒号
学号=20230005 姓名=钱七   ← 带键名的写法
```

不知道怎么写？点「**导出示例 TXT 文件**」，程序会存一个 `学生信息表_示例.txt` 给你，照着改就行。也可以点「填入示例」直接把示例内容填进文本框。

**补全是双向的**：

```
文件名只有学号   20230001_第一次作业.docx
   + 信息表 20230001 → 张三
   = 第一次作业_20230001_张三.docx      ← 姓名被补出来了

文件名只有姓名   李四_第二次作业.docx
   + 信息表 李四 → 20230002
   = 第二次作业_李四_20230002.docx      ← 学号被补出来了
```

信息表留空也能用，此时程序就只用文件名里自带的信息。

#### ⑤ 学号与姓名至少要有一个（不合格会标红）

**这是硬性要求**：一个文件如果既没有学号、也没有姓名，就没法可靠地判断它是谁交的。

程序会把这类文件判为**不合格**：**不会被改名**，并在预览表格里**整行标红**：

```
状态     原文件名                  新文件名  识别结果  判定依据
不合格   孤零零.docx               —        —        仅一段「孤零零」，缺少学号或姓名
```

同时弹窗提醒你「有 N 个文件的文件名中既无学号也无姓名」。

**会被判为不合格的情形**：

| 情形        | 说明                   |
| --------- | -------------------- |
| 只有 1 段    | 无论内容是什么，都缺了另一项       |
| 两段都是数字    | 无法判断哪个是学号，也确定不了作业名   |
| 三段及以上     | 不符合两段识别规则            |
| 固定格式下语义不符 | 声明为学号的段写着「第一次作业」这类内容 |

五种状态的颜色区分：

| 状态      | 底色     | 字色     | 含义                     |
| ------- | ------ | ------ | ---------------------- |
| 将改名     | 浅绿     | 深绿     | 会被改名                   |
| 无需改动    | 无      | 无      | 新旧名字相同                 |
| **不合格** | **浅红** | **深红** | **缺学号姓名或不予识别，标红警示，不改** |
| 跳过      | 浅黄     | 深黄     | 结构不符或重名冲突，不改           |

预览表格共 5 列：**状态 / 原文件名 / 新文件名 / 识别结果 / 判定依据**。
  
「识别结果」列显示程序认出的学号与姓名，「判定依据」列写明命中了哪条规则，
  
例如 `[数字+文本] 数字段「20230001」判为学号，文本段「张三」判为作业名`。
  
这一列的作用是让你能核对程序"有没有认对人"，而不只是看结果。

#### ⑥ 操作流程被强制分成两步

这是刻意的设计：

```
① 预览改名结果   →   看清楚「谁会被改成什么」「谁不会被改、为什么」
② 确认执行改名   →   弹出确认框，点了「是」才真的改
```

注意「② 确认执行改名」按钮在预览之前是**灰的，点不了**。这是从界面层面保证你不会误操作。

**冲突处理**：如果算出的新名字已经被占用（不管是被已有文件占用，还是同一批里两个文件算出了同一个新名字），程序会**跳过它并在预览里写明原因**，绝不覆盖。

```
【将被跳过（不会被修改）】
   4. 20230402_沈十七_读书笔记.txt
      原因：目标名「读书笔记_20230402.txt」已被占用（读书笔记_20230402.txt），为避免覆盖已跳过
```

### 需求 3 · 归档报告

**两种分类方式**：

- **按文件类型**：`.docx` → `Word文档/`，`.pdf` → `PDF文档/`，`.txt` → `文本文件/`
- **按学期**：根据文件的**修改时间**落在哪个学期区间来分

#### 按学期归档的依据是什么？

判定依据只有一个：**文件的修改时间（mtime）**，即文件属性里那个"修改日期"。
  
程序不看文件名里的"第一次作业"这类字样，也不看文件创建时间。

具体做法是拿 mtime 去和一张**学期区间表**逐条比对，落在哪个区间就归到哪个学期。
区间表**可以在界面上直接编辑**（需求3页面的「学期区间设置」，默认收起，点标题展开）。
内置默认值覆盖两个学年共四个学期：

```
2025-2026-1, 2025-09-01, 2026-01-15
2025-2026-2, 2026-02-20, 2026-07-10
2026-2027-1, 2026-09-01, 2027-01-15
2026-2027-2, 2027-02-20, 2027-07-10
```

**界面上的「学期区间设置」区**：

| 控件 | 作用 |
|---|---|
| 文本输入框 | 每行一条 `学期名, 开始日期, 结束日期`，日期格式 `YYYY-MM-DD` |
| 填入默认区间 | 一键恢复成上面那份内置默认值 |
| 校验区间 | 检查格式是否合法，把结果显示在右侧状态标签 |
| 放大 ⤢ | 区间条数多时整屏编辑 |

日期写法很宽容：`2026-9-1`（省略前导零）、`2026/9/1`（斜杠分隔）、中文逗号
`，` 分隔都能识别，程序会自动规范化为 `2026-09-01`。但像 `2026-02-30` 这种
**不存在的日期**会被拒绝并指出行号。

命令行版本用 `--semester-file` 指定一个 TXT 文件（格式同上），不指定则用内置默认值：

```bash
python cli.py archive E:/计协应聘/测试 --mode semester --semester-file 我的校历.txt --yes
```

三条重要细节：

1. **默认区间只是估计值，请按你学校的校历改。** 各校开学与放假日期不同，
   秋季学期大致 9 月初到次年 1 月中、春季学期 2 月下旬到 7 月上旬。
   直接在界面「学期区间设置」里改即可，不用动代码。
2. **结束日期包含当天。** 判断时把结束日期的时刻补到 `23:59:59`，否则 1 月 15 日
   当天提交的文件会落到区间之外。
3. **落不进任何区间的文件归入 `未归类/`，并在报告里列出其修改时间。** 报告会多出
   一个「未归类明细」区块，逐条给出文件名和实际 mtime，你据此把缺失的学期补进
   区间表、再归档一次即可归位。

> **要注意的坑**：mtime 是"最后一次修改"的时间，不是"交作业"的时间。如果一份 2025 秋季
> 学期的作业在 2026 年 3 月被重新保存过（比如补了个封面），它的 mtime 就会变成 3 月，
> 从而被错误归入春季学期。依赖 mtime 的归档都绕不开这一点，人工复核时留意即可。

归档完成后会生成一份报告，回答三个问题：

```
【汇总】
  成功移动：17 个
  跳过未动：0 个
  本次合计：17 个

【分类统计】
  2026-2027-1：17 个

【跳过明细】
  （无跳过文件，本次全部处理成功）

【未归类明细】
  以下文件的修改时间不落在任何已配置的学期区间内，
  它们的实际修改时间如下，可据此补充学期区间后重新归档：

    1. 2028年的老文件.docx
       修改时间：2028-03-01 14:22

  处理办法：在「学期区间设置」中补上覆盖上述时间的区间，
  再执行一次归档即可把文件移入对应学期文件夹。
```

（「未归类明细」区块只在确有文件落在区间外时才出现。）

报告会**自动存盘**到 `.homework_organizer/reports/` 下，带时间戳，不会互相覆盖。

**撤销**：点「② 撤销上次操作」可以把最近一次归档的文件全部搬回原位。

原理是每次归档都会把「谁从哪搬到哪」记进 `.homework_organizer/journal.json`，撤销时反向执行即可。

撤销同样遵守「不覆盖」原则——如果原位置已经有东西了，会跳过并报告，而不是覆盖。

### 新增功能 · 作业检查

这是本次新增的功能。**导入任意检索信息，与所有文件名逐段比对，统计每一条信息的识别情况与字数达标情况，
产出一张汇总表；达标份数 ≥ 1 标绿，否则标红；全部标绿时给出一个总绿勾，存在标红则弹窗提示。**

**支持的格式**：`.docx`、`.pdf`、`.txt`、`.md`、`.xlsx`

#### ⓪ 字数要求 —— 只在本页设置

进入「新增 · 作业检查」页后，界面自上而下依次是：**检查规则说明 → 检索信息 →
字数要求 → 按钮行 → 汇总表 → 逐文件明细表**。

「字数要求」是一个独立分组，里面是一个数字输入框（默认 **500 字**，步长 100）：

```
字数要求
   不低于 [500 字]   填 0 表示不限制字数，所有文件都会被判为达标。
```

**它只出现在这一页。** 之前它被放在顶部公共区，切到改名、归档等标签页时也会显示，
容易让人误以为那些功能同样受字数约束。移入本页后，**只有做作业检查时才看得到它**。

#### ① 检索信息 —— 每行一条，任意内容

点「填入示例」会给出这样一段：

```
# 每行一条检索信息，与文件名的每一段做完全匹配
# 可以写姓名、学号、作业名等任意内容
# 以 # 开头的是注释行，空行会被忽略
张三
李四
王五
20230101
第一次作业
```

**匹配口径是「完全匹配段」**，和作业归类完全一致：文件名先按 `_`、`+`、空格切成任意多段，
某一段与检索信息**整段相等**才算命中。所以「张三」**不会**命中「张三丰」——这是刻意的，
避免子串包含带来的误统计。一个文件可以同时命中多条信息，于是在汇总表里会同时计入每一行。

#### ② 汇总表 —— 四列数字，一眼看穿

| 输入信息  | 识别份数 | 达标份数 | 未达标份数 | 读取失败 |
| ----- | ---- | ---- | ----- | ---- |
| 张三    | 2    | 1    | 0     | 1    |
| 李四    | 1    | 0    | 1     | 0    |

- **识别份数**：文件名命中该条信息的文件总数
- **达标份数**：其中字数 ≥ 阈值的份数
- **未达标份数**：其中字数 < 阈值的份数
- **读取失败**：文件打不开（如扫描件 PDF），**单独一列，既不计入未达标、也不拉低绿标**

#### ③ 标色规则与总绿勾

**判定条件只有一条：达标份数 ≥ 1 就标绿，否则标红。**

| 状态 | 底色 | 字色 | 触发条件 |
| --- | --- | --- | --- |
| 通过 | 淡绿 `#e8f5e9` | 深绿 `#1b5e20` | 达标份数 ≥ 1（哪怕还夹着未达标） |
| 未通过 | 淡红 `#ffe0e0` | 深红 `#c00000` | 达标份数为 0（含一条都没识别到） |

- 所有行都标绿时，表头显示 **`✓ 全部通过`**，底部徽标同步变绿
- 存在标红行时，表头显示 **`⚠ 未通过：李四`**（点名到具体信息），并弹出提示窗说明三种常见原因：
  该信息没在文件名中出现、文件里没有该信息对应的文档、文件名里的那一段与检索信息不完全一致

**⚠ 一个刻意的设计**：汇总表**为空时不算「全部通过」**。否则一条信息都没填的时候，
界面会给出一个毫无意义的绿勾，误导用户以为检查过了。

#### ④ 逐文件明细表（保留）

原来的逐文件明细表**完整保留**在汇总表下方，仍然逐行显示每个文件的字数、达标状态与标红原因。
汇总表是「按检索信息看」，明细表是「按文件看」，两者互补。

#### ⑤ 标红效果（明细表的三套配色）

| 状态     | 底色           | 字色           | 含义           |
| ------ | ------------ | ------------ | ------------ |
| ★ 字数不足 | 淡红 `#ffe0e0` | 深红 `#c00000` | 需要退回重做的作业    |
| 统计失败   | 淡黄 `#fff8e1` | 深黄 `#8d6e00` | 文件读不出来，需人工检查 |
| 达标     | 淡绿 `#e8f5e9` | 深绿 `#1b5e20` | 正常           |

**字数怎么算的？** 这一点必须说清楚，因为中英文口径差异很大：

- 每个**中文字符**算 1 个字：`今天天气很好` = 6 字
- 每个**英文单词**算 1 个字（不是每个字母）：`hello world` = 2 字
- **标点、空格不算**字数

**判定规则**：低于阈值是**严格小于**。即阈值设 500 时，499 字不合格，**500 字算合格**。

**★ 一个重要设计**：「统计失败」和「字数不足」是分开处理的。

一个损坏的 PDF 打不开，它的字数是 0。但程序**不会**因此把它标红——因为「读不出来」不等于「学生没写够」。这类文件单独用黄色标记，提示你去人工检查。

### 新增功能 · 作业归类

**它解决什么问题**：收上来一批作业，文件名五花八门，但每个文件里都写着作业名。
想按作业名分文件夹收好，又不想一个个手动拖。

**它怎么做**：把文件名按分隔符切成**任意多段**，每一段都拿去和「关键词表」比对，
命中哪一段就用**那一段本身**当文件夹名，把文件归进去。缩略流程：

```
扫描文件名 → 切成任意多段 → 逐段与「关键词表」比对 → 预览 → 确认 → 移动文件
                  ↑                                    ↑
            只读，不动文件                      这一步才真正动文件
```

#### ① 逐段匹配，段数不限

这是本模块的核心机制。文件名按 `_`、`+`、空格切段后，**每一段都会单独和表比对**，
段数**不设上限**——两段、三段、五段都一样处理：

| 文件名 | 切出的段 | 命中（表含「第一次作业 / 张三 / 20230101」） |
|---|---|---|
| `第一次作业_张三_20230101.docx` | 第一次作业 / 张三 / 20230101 | **三段全中** |
| `读书笔记_李四_20230202.txt` | 读书笔记 / 李四 / 20230202 | 读书笔记、李四 |
| `张三_第一次作业.docx` | 张三 / 第一次作业 | 张三、第一次作业 |
| `随便起的名字.txt` | 随便起的名字 | 无 |

段数不受限制，意味着你不必先把文件名规范成固定格式，**只要里面有能对上表的内容就能归类**。

#### ② 关键词表 —— 表里写什么就匹配什么

表里可以**混写作业名、姓名、学号**，没有任何类别区分，程序一视同仁：

```
# 井号开头的是注释，程序自动忽略
第一次作业
第二次作业
数据结构实验
算法分析报告
读书笔记
课程总结
张三
李四
王五
20230101
```

界面提供四个按钮：**导入 TXT** / **填入示例** / **导出示例** / **清空**。
「关键词表」同样配了**放大按钮**，表很长时可以近全屏编辑。

#### ③ 命中多段怎么办 —— 每个命中项各放一份

如果一个文件同时命中好几段（比如上表第一行三段全中），程序会**为每个命中项各建一个文件夹**：
文件本体放进第一个命中的文件夹，其余文件夹里各放一份**副本**。效果就是
「此文件同时位于多处」。

| 文件名 | 第一次作业/ | 张三/ | 20230101/ |
|---|---|---|---|
| `第一次作业_张三_20230101.docx` | 本体 | 副本 | 副本 |

副本保留原文件的修改时间。副本会占用额外的磁盘空间，这是**多文件夹并存**的必要代价——
若你只想要一个去处，就把表收窄到只有作业名。

#### ④ 一段都没命中的文件 —— 保持原地不动

任何一段都对不上表的文件，程序**不移动它**，原因是：可能你漏填了关键词、
也可能文件名本身写错了，贸然移动反而增加你找回文件的成本。

这类文件会出现在两个地方提醒你：

| 位置 | 表现 |
|---|---|
| 归类预览表 | 状态列标**红**写「未命中」，目标文件夹列写「**（不移动）**」 |
| 整理报告 | 单独一节「**未命中关键词 · 未移动**」，逐条列出文件名与原因 |

对照表如下：

| 情况 | 状态列 | 会移动吗 |
|---|---|---|
| 命中了 1 段 | 将归类（绿） | ✅ 移入 `该段/` 文件夹 |
| 命中了 N 段 | 将归类（绿，标注「N 个」） | ✅ 本体进第 1 个，其余 N-1 个文件夹各放副本 |
| 一段都没命中 | 未命中（红） | ❌ **原地不动**，仅报告提示 |
| 关键词表留空 | —— | ❌ **不执行**，提示你先填表 |

#### ⑤ 关键词表是必需的

与「按作业名归档」不同，本机制**完全依赖关键词表**：
没有表就没有比对依据。因此表留空时：

- 右上角计数会标**红**显示「关键词表为空，无法归类」；
- 「① 预览归类结果」按钮**变灰不可点**，鼠标悬停会说明原因；
- 即使绕过界面直接调核心函数，也会抛出 `ValueError` 而不是静默地什么都不做。

#### ⑥ 文件名不会被修改

本模块**只移动文件**，不改名。移入 `第一次作业/` 后，文件名仍是你原来的名字。
需要改名请用「需求2 · 批量改名」——两个功能各管一件事，互不干扰。

#### ⑦ 操作流程同样被强制分成两步

与需求 2、需求 3 一致：

1. 点「**① 预览归类结果**」——只读，填好预览表，**不动任何文件**；
2. 核对预览表，确认无误后点「**② 确认执行归类**」——弹出确认框，点「是」才真正移动。

「② 确认执行归类」按钮在预览之前是**灰色不可点**的，防止误操作。

#### ⑧ 支持撤销

归类完成后，若结果不符合预期，点「**③ 撤销上次操作**」即可把所有文件移回原位。
撤销时不仅还原本体，还会**自动清理归类时产生的所有副本**，让根目录完全恢复原样。
撤销记录与需求 3 共用同一套日志（`.homework_organizer/journal.json`），
因此**按学期归档和按作业归类，撤销时都恢复最近一次操作**。

#### ⑨ 实际效果示例

以项目自带的演示数据（`测试/` 目录，16 个文件）为例，关键词表填
`第一次作业 / 第二次作业 / 数据结构实验 / 算法分析报告 / 读书笔记 / 课程总结 / 张三 / 李四`：

```

    ├── 读书笔记_冯十二_20230202.txt
    ├── 20230101_张三_作业.pdf
    └── ...（共 16 个）

整理后
    ├── 第一次作业/          2 个   ← 含本体
    ├── 第二次作业/          2 个
    ├── 数据结构实验/         2 个

    ├── 读书笔记/            4 个
    ├── 课程总结/            1 个
    ├── 张三/               1 个   ← 全部是副本
    ├── 李四/               1 个   ← 副本
    ├── 随便起的名字.txt            ← 原地不动：一段都没命中
```

## 四、命令行版本（可选）

除了图形界面，也提供了一个命令行版本，适合快速查看或用脚本自动化。

```bash
# 扫描列出
python cli.py scan E:/计协应聘

# 只看 pdf 和 docx
python cli.py scan E:/计协应聘 --ext .pdf .docx

# 改名：默认只预览，不会改任何文件
python cli.py rename E:/计协应聘

# 改名：真正执行（必须同时加 --apply --yes）
python cli.py rename E:/计协应聘 --apply --yes

# 作业检查（按检索信息汇总；存在标红项时以退出码 2 结束）
python cli.py wordcount E:/计协应聘 --min 500
python cli.py wordcount E:/计协应聘 --min 500 --info-file 检索信息.txt

# 看看检索信息该怎么写
python cli.py wordcount E:/计协应聘 --show-info-sample

# 归档
python cli.py archive E:/计协应聘 --mode extension --yes

# 按作业名归类（--title-file 指定作业名表；不加则识别出什么就按什么归类）
python cli.py archive E:/计协应聘 --mode title --title-file 作业名表.txt --yes

# 按段归类（--keyword-file 指定关键词表，可混写作业名/姓名/学号；不加则用内置示例表）
python cli.py archive E:/计协应聘 --mode segment --keyword-file 关键词表.txt --yes

# 撤销
python cli.py undo E:/计协应聘 --yes
```

**改名命令可以自选原格式、并提供信息表**：

```bash
# 默认即为自动识别，无需额外参数
python cli.py rename E:/计协应聘

# 原文件名是「姓名_学号_作业名」，指定固定格式
python cli.py rename E:/计协应聘 --source-format name-id-title

# 提供学生信息表，按学号补出姓名
python cli.py rename E:/计协应聘 --roster 名单.txt --template "{title}_{id}_{name}"

# 提供作业白名单，指定哪些是作业名（仅在 --source-format auto 时生效）
python cli.py rename E:/计协应聘 --title-whitelist 作业白名单.txt

# 看看信息表 / 作业白名单该怎么写
python cli.py rename E:/计协应聘 --show-roster-sample
python cli.py rename E:/计协应聘 --show-title-sample
```

`--source-format` 的默认值是 `auto`（自动识别）。也可指定固定排列，
  
取值用连字符连接各段，可选段为 `id` / `name` / `title` / `extra`：

| 取值                    | 含义           |
| --------------------- | ------------ |
| **`auto`**            | **自动识别（默认）** |
| `id-name-title`       | 学号_姓名_作业名    |
| `name-id-title`       | 姓名_学号_作业名    |
| `id-title`            | 学号_作业名       |
| `name-title`          | 姓名_作业名       |
| `title-id`            | 作业名_学号       |
| `title-name`          | 作业名_姓名       |
| `id-name-title-extra` | 学号_姓名_作业名_序号 |

命令行版本里，**所有会修改文件的操作都需要显式加 `--yes`**，这是为了防止脚本误触发。

### 退出码

`wordcount`（作业检查）子命令用退出码表达检查结果，方便接进自动化脚本或 CI：

| 退出码 | 含义 |
| --- | --- |
| `0` | 执行成功，且**所有检索信息都通过**（含检索信息为空的情况） |
| `1` | 参数错误、目录不存在等常规失败 |
| `2` | 执行成功，但**存在标红（有信息未通过）** —— 用于「让脚本知道检查没过」 |

例如在脚本里：

## 五、项目结构

```
homework_organizer/
├── __init__.py
├── core/                    ← 纯逻辑层，不依赖 PySide6
│   ├── __init__.py
│   ├── scan.py             需求1：扫描与列出
│   ├── rename.py           需求2：批量改名（自动识别 + 可变格式 + 防覆盖）
│   ├── roster.py           需求2：学生信息表（学号 ↔ 姓名对照）
│   ├── archive.py          需求3：归档 + 报告 + 撤销；作业归类：按段匹配关键词表
│   └── wordcount.py        新增：作业检查（字数统计 + 按检索信息汇总）
└── gui/                     ← 界面层
    ├── __init__.py
    ├── app.py              程序入口
    └── main_window.py      主窗口（五个标签页）

tests/
└── test_core.py            201 个单元测试

cli.py                      命令行入口
run.py                      启动图形界面
make_demo_data.py           生成演示数据
```

**为什么把 `core` 和 `gui` 分开？**

因为这样核心逻辑可以脱离界面单独测试。`core/` 里的模块完全不知道 Qt 的存在，它们只做纯逻辑——读目录、算新名字、搬文件。这让：

1. 逻辑 bug 和界面 bug 可以分开定位
2. 将来要换成 Web 界面或别的界面，`core/` 一行都不用改
3. 测试不需要启动图形界面，跑得飞快（201 个测试 约 20 秒）

## 六、安全设计

这个工具会修改文件，所以安全是重点。以下是所有安全措施：

**1. 只读与写操作分离**

`scan.py`、`wordcount.py`、`roster.py` 只读，永不修改文件。`rename.py` 和 `archive.py` 才会写，且都需要用户明确确认。

**2. 强制预览**

需求 2 的改名流程被拆成「计算计划」和「执行计划」两个阶段，中间必须经过用户确认。代码结构上就保证了「不经过预览就没法执行」。

**3. 绝不覆盖**

四个地方都做了防覆盖检查：

- 改名预览时：目标名已占用 → 跳过
- 改名执行时：**再次检查**目标名（防止预览和执行之间文件系统变化）→ 跳过
- 归档时：目标位置已有同名文件 → 跳过
- 撤销时：原位置已有同名文件 → 跳过


**4. 批内冲突防护**

同一批改名里，如果两个文件算出了同一个新名字，只批准第一个，第二个跳过。没有这层防护，后一个会静默覆盖前一个。

**5. 不合格文件不改名**

文件名里既没有学号也没有姓名、或声明为学号/姓名的那一段内容明显不符（如把"第一次作业"当成学号）的文件，会被判为不合格：**标红提示，且不参与改名**。这样既提醒了教师，也避免了生成错误的名字。

**6. 可撤销**

归档操作全部记入日志，随时可以一键回滚。

**7. 单点失败不影响整体**

批量处理时每个文件单独 `try/except`。一个文件因为被 Word 占用而改名失败，不会导致剩下的文件都不处理。

**8. 读不出的信息表不影响主流程**

信息表解析失败只是静默跳过那一行；查询不到某个学号也只返回 `None`，不会抛异常中断整批处理。

**9. 数据留在原地**

工具自己的日志和报告存在 `.homework_organizer/` 子目录里，不污染你的作业文件夹，也不会写到别的地方去。

## 八、常见问题

**Q：为什么改名的按钮一开始是灰的？**

A：因为必须先预览。这是防止误操作的设计——不让你有「直接改」的机会。

**Q：我的文件名是「姓名_学号_作业名」，程序不认怎么办？**

A：默认的「自动识别（推荐）」本来就认这种排列——它不看固定顺序，而是看**有几段、每段是什么类型**。只有当文件名本身推断不出来（例如三段以上、或两段全是数字）时，才需要在「原文件名格式」下拉框里改成固定的「姓名_学号_作业名」，把顺序钉死。

**Q：自动识别认错了怎么办？**

A：两种办法，按推荐顺序：

1. **填「作业白名单」**——把正确的作业名写进去，与表完全一致的那一段会被直接认定为作业名，优先于程序的任何猜测。这是最省事的办法，尤其适合「宏观经济学」这类不含「作业/报告/实验」字样、程序必然猜错的作业名。
2. **切到固定排列**——把「原文件名格式」从「自动识别（推荐）」改成对应的固定结构，程序会严格按你选的顺序取字段，不再自行推断。

**Q：填了作业白名单，为什么有些文件还是标红了？**

A：因为白名单**只能决定哪一段是作业名，不能代替学号或姓名**。需求里有条硬性要求：学号与姓名至少要有一个。像 `随便起的名字.docx` 这种只有一段的文件，即使写进白名单、确实被认成了作业名，也因为没有学号姓名而照样标红。

**Q：作业白名单在「固定排列」格式下填了没反应？**

A：这是有意的。固定排列下作业名由你指定的字段位置直接决定，不需要也无法用白名单干预。程序检测到这种情况会弹窗提示，并说明白名单本次不参与判断。想用白名单，把「原文件名格式」切回「自动识别」即可。

**Q：什么样的文件名会被标红（不予通过）？**

A：按段数分四种情况：

| 文件名形态                | 处理                                       |
| -------------------- | ---------------------------------------- |
| 只有一段（无论文本还是数字）       | 标红，缺少学号或姓名                               |
| 一段数字 + 一段文本          | 文本段直接当作业名                                |
| 两段都是文本               | 先找含「作业」字样的那段；两段都含就取后置的；两段都不含也取后置的，另一段当姓名 |
| 一段数字 + 两段文本（三段，数字位置任意） | 数字段作学号，另两段文本按上面的「两段文本」规则定作业名 |
| 其余情况（四段及以上、两段都是数字、三段里有多个数字段） | 标红，不予识别 |

段与段之间只认 `_`、`+` 和空格（半角/全角都算）。

**Q：为什么「作业_报告.docx」的作业名是「报告」而不是「作业」？**

A：因为两段文本都含作业字样，按补充规则取后置的那段，所以作业名是「报告」，「作业」被当作姓名段。

**Q：文件被标红说「不像学号」，但它确实是学号？**

A：固定排列模式下学号段应只含字母、数字和连字符；自动识别模式下则是「这一段全是数字」才算学号。如果你的学号里带了别的符号（比如中文、括号），会被判为文本段。这种情况下把「原文件名格式」选对（例如改成「姓名_作业名」，让程序不必猜），或者把该文件单独处理即可。

**Q：信息表里查不到的学号，会把学号也抹掉吗？**

A：不会。查不到时程序保留文件名里原本的学号，只在说明栏提示「不在信息表中」。

**Q：按学期归档时，所有文件都进了「未归类」，怎么回事？**

A：说明这些文件的修改时间没落在你当前的学期区间里。最常见的原因是
**默认区间表只覆盖 2025-2026 与 2026-2027 两个学年**，如果文件是更早或更晚的，
就会全部落到区间外。解决办法：展开需求3页面的「学期区间设置」，按你学校的
实际校历补充区间，点「校验区间」确认格式无误，再重新归档一次即可。
报告里的「未归类明细」区块逐条列出了这些文件的真实修改时间，照着补区间最快。

**Q：归档规则设错了怎么办？**

A：点「② 撤销上次操作」即可全部搬回原位。日志记录在 `.homework_organizer/journal.json`。

**Q：「作业归类」和「需求3 · 归档报告」有什么区别？**

A：归档报告按**类别或学期**分组（如 `Word文档/`、`2025-2026-1/`），依据是扩展名或文件修改时间；
作业归类按**文件名里命中的段**分组（如 `第一次作业/`、`张三/`），依据是关键词表。
两者**共用同一套底层逻辑**（同一份 `archive.py`、同一个撤销日志），只是分类依据不同。

**Q：为什么同一个文件出现在好几个文件夹里？**

A：因为它**同时命中了好几段**。按段归类会把文件名切成任意多段逐段比对，
每命中一段就为那一段建一个文件夹。本体放进第一个命中的文件夹，其余文件夹里各放一份**副本**，
效果就是「此文件同时位于多处」。副本会占额外磁盘空间——若你只想要一个去处，
把关键词表收窄到只留作业名即可。

**Q：作业归类预览里显示「未命中」，文件去哪了？**

A：**没动，还在原地**。这是按你的要求设定的：一段都没命中的文件不移动，
只在预览表（标红）和整理报告的「未命中关键词 · 未移动」区块里列出来提醒你。
确认是漏填了就补进关键词表重新归类；确认是文件名写错了就用「需求2 · 批量改名」修正。

**Q：为什么关键词表必须填？留空不是更方便吗？**

A：本机制**完全依赖这张表**——没有表就没有比对依据，无法判断该归到哪个文件夹。
所以表留空时程序**直接拒绝执行**：预览按钮变灰、计数标红提示、核心函数抛 `ValueError`，
而不是静默地什么都不做让你误以为成功了。

**Q：作业归类会改文件名吗？**

A：不会。它只移动（或复制）文件。移入 `第一次作业/` 后文件名还是你原来的名字。

**Q：撤销后副本会残留吗？**

A：不会。撤销时会先**清理归类产生的所有副本**，再把本体移回原位，
根目录的文件数会完全恢复到归类之前。

**Q：扫描件 PDF 的字数是 0，会把它标红吗？**

A：在**逐文件明细表**里会标红（因为 0 < 阈值），但这确实是扫描件的固有限制——图片型 PDF 里没有文字层，需要 OCR 才能提取。在**汇总表**里则不会：它被计入「读取失败」那一列，既不计入未达标，也不影响该行的绿标。

**Q：作业检查汇总表里的「读取失败」和「未达标」有什么区别？**

A：这是刻意分开的两件事。**未达标**是文件读出来了、但字数不够，属于学生的问题；**读取失败**是文件根本打不开（扫描件 PDF、加密文档等），属于文件本身的问题。混在一起会冤枉学生，也会让绿标失真——所以读取失败单独成列，不参与「达标份数 ≥ 1 就标绿」的判定。

**Q：为什么我填了检索信息，汇总表里那一行的「识别份数」是 0？**

A：说明**没有任何文件的文件名里有一段与它完全相等**。注意匹配是「整段相等」而非包含：写「张三」只能命中文件名里恰好是「张三」的那一段，不会命中「张三丰」；文件名里的段还要求先按 `_`、`+`、空格切开。常见原因是名字里多/少了字、或者那一整段里混了别的字符。

**Q：一条检索信息一份都没达标就报「未通过」，太严了吧？**

A：这正是你要的判定口径：**达标份数 ≥ 1 才标绿，否则标红**。注意「1 份达标」就够了——哪怕这一行里同时还有 9 份未达标，该行依然是绿的（未达标份数会如实显示在对应列里）。你若想更严格，看「未达标份数」那一列即可。

**Q：检索信息留空会怎样？**

A：可以照常做字数检查（明细表照常标红），但**不会生成汇总表**——因为汇总表就是「按检索信息逐条统计」，没有信息就没有行可统计。此时界面会明确提示「本次不生成汇总表」，而不是给一个空的绿勾（空表刻意不算「全部通过」，避免误导）。

**Q：文件改不了名，报「Permission denied」？**

A：通常是文件正被 Word/Excel/PDF 阅读器打开。关掉程序再试。

**Q：模板里能写中括号、空格之类的吗？**

A：能。程序会自动处理 Windows 文件名不允许的字符（`< > : " / \ | ? *` 会被替换成下划线）。

**Q：能用来整理别的文件吗？**

A：可以。归档、作业检查、扫描列表这些功能完全通用。改名功能默认会按「段数与内容类型」自动推断文件名里的学号/姓名/作业名；如果你的文件名不是「两段、一段数字一段文本」这种结构，就到「原文件名格式」下拉框里选一个固定排列来精确定位。
